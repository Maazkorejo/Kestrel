# API Specification & Data Contracts

## Project: Kestrel AI (AI-Native Cybersecurity IDE & DevSecOps Engine)
**Tagline:** Hunt flaws. Ship armor.

---

## 1. Overview
This document defines the REST API contracts, data models, and JSON schemas between the FastAPI backend and the client applications (Web, Desktop, and CLI). All models follow Pydantic v2 conventions on the backend and correspond to TypeScript interfaces on the frontend.

All endpoints are organized into modular internal and external routers mounted under `/api`.

---

## 2. Core Data Models

### 2.1 Finding (`Finding`)
Represents an individual security finding generated by deterministic static analysis engines.

```json
{
  "id": "vuln_cwe89_line23",
  "rule_id": "bandit-B608-sql-injection",
  "title": "SQL Injection via Unsanitized Formatting",
  "description": "Direct string concatenation into SQL query allows unauthorized query execution or authentication bypass.",
  "cwe_id": "CWE-89",
  "severity": "CRITICAL",
  "line_start": 23,
  "line_end": 23,
  "code_snippet": "query = f\"SELECT id, username, role FROM users WHERE username = '{username}'\"",
  "scanner": "ast",
  "architectural_role": "SINK",
  "enclosing_function": "login"
}
```

* **Severity Levels:** `CRITICAL`, `HIGH`, `MEDIUM`, `LOW`, `INFORMATIONAL`
* **Architectural Roles:** `SINK`, `SOURCE`, `VALIDATION_GAP`, `TRIGGER_POINT`

### 2.2 Threat Intelligence Item (`ThreatRecord`)
Represents authoritative vulnerability data fetched via Tavily Search.

```json
{
  "cve_id": "CVE-2023-XXXX",
  "title": "SQL Injection in SQLite Driver Implementations",
  "source_url": "https://nvd.nist.gov/vuln/detail/CVE-2023-XXXX",
  "published_date": "2023-11-15",
  "summary": "Improper neutralization of special elements in query construction leads to arbitrary query manipulation.",
  "cvss_score": 9.8,
  "mitigation": "Use parameterized queries with placeholder substitution tuples rather than formatted string literals."
}
```

### 2.3 Remediation Patch (`RemediationResult`)
Represents AI root-cause analysis and unified git diff patch generated by NVIDIA Nemotron.

```json
{
  "finding_id": "vuln_cwe89_line23",
  "root_cause": "The username variable is formatted directly into the SQL query string without escaping or parameter binding.",
  "exploit_scenario": "An attacker can input `' OR '1'='1` in the username field to bypass password verification and gain administrative access.",
  "patch_summary": "Replaced direct f-string formatting with parameterized query markers and passed parameters as a tuple.",
  "diff": "--- a/auth_service.py\n+++ b/auth_service.py\n@@ -21,3 +21,3 @@\n-    query = f\"SELECT id, username, role FROM users WHERE username = '{username}'\"\n-    cursor.execute(query)\n+    query = \"SELECT id, username, role FROM users WHERE username = ? AND password = ?\"\n+    cursor.execute(query, (username, password))\n",
  "patched_full_code": "..."
}
```

## 3. Internal API Endpoints (`/api/...`)

### 3.1 Workspace & File System (`/api/workspace`)
* **POST `/api/workspace/open`**: Opens a directory path on disk and returns its hierarchical file tree.
* **GET `/api/workspace/tree`**: Returns the file tree of the currently active workspace.
* **GET `/api/workspace/system-directories`**: Returns standard user directories (`home`, `desktop`, `downloads`, `documents`).
* **POST `/api/workspace/read`**: Reads file content from disk with size and language detection.
* **POST `/api/workspace/write`**: Saves modified file content directly to disk.
* **POST `/api/workspace/create`**: Creates a new file or directory inside the active workspace.
* **GET `/api/workspace/history`**: Retrieves telemetry and audit run records from SQLite database.
* **POST `/api/workspace/clear-cache`**: Purges cached AST remediations and findings for zero-retention privacy.

### 3.2 Authentication & User Profiles (`/api/auth`)
* **GET `/api/auth/me`**: Returns the active authenticated user profile by bearer token or session.
* **POST `/api/auth/register`**: Registers a new user with PBKDF2 password hashing; returns session token.
* **POST `/api/auth/login-credentials`**: Authenticates email and password against PBKDF2 hash.
* **POST `/api/auth/guest`**: Issues an ephemeral offline guest session profile.
* **POST `/api/auth/login`**: Direct profile login helper for OAuth flows.
* **POST `/api/auth/logout`**: Revokes session token and returns to guest mode.
* **GET `/api/auth/saved-accounts`**: Lists previously authenticated accounts saved on this device.
* **POST `/api/auth/switch-account`**: Activates a specified saved user profile.

### 3.3 Git Version Control (`/api/git`)
* **GET `/api/git/status`**: Returns branch name, staged files, unstaged files, and untracked files.
* **POST `/api/git/stage`**: Stages specified file or all files in git index.
* **POST `/api/git/unstage`**: Unstages specified file from git index.
* **POST `/api/git/commit`**: Creates a git commit with provided commit message.
* **POST `/api/git/push`**: Pushes local commits to upstream repository.
* **POST `/api/git/pull`**: Pulls updates from upstream repository.

### 3.4 Project Search & Replace (`/api/search`)
* **POST `/api/search/project`**: Performs multi-file search across workspace with regex, case-sensitivity, and whole-word matching.
* **POST `/api/search/replace-all`**: Replaces matching text across all workspace files.

### 3.5 Cyber Terminal (`/api/terminal`)
* **POST `/api/terminal/exec`**: Executes security commands (`scan`, `bandit`, `yara`, `cve`, `edb`, `ext`, `status`) or safe workspace shell commands.

### 3.6 Settings & Extensions (`/api/settings` & `/api/extensions`)
* **GET `/api/settings/current`**: Returns runtime model configuration and masked API credentials.
* **POST `/api/settings/save`**: Updates runtime API keys, model parameters, and offline flags.
* **GET `/api/extensions/search`**: Queries Open VSX Marketplace for cybersecurity extensions.
* **POST `/api/extensions/install`**: Installs an extension into workspace.
* **POST `/api/extensions/uninstall`**: Removes an extension from workspace.

### 3.7 Static Scanner & SARIF (`/api/scan` & `/api/export`)
* **POST `/api/scan/static`**: Runs in-memory deterministic AST analysis on submitted source code.
* **POST `/api/scan/workspace`**: Recursively audits all files in active workspace and identifies dependency CVEs.
* **POST `/api/export/sarif`**: Generates OASIS SARIF 2.1.0 report for GitHub Code Scanning.

### 3.8 Exploit Sandbox & Attack Simulator (`/api/sandbox` & `/api/simulator`)
* **GET `/api/sandbox/status`**: Returns Docker daemon availability and sandbox engine status.
* **POST `/api/sandbox/simulate`**: Runs vulnerable and patched code in isolated sandboxes to verify mitigation.
* **GET `/api/simulator/scenarios`**: Catalog of supported attack scenarios (command injection, SQLi, path traversal, deserialization).
* **POST `/api/simulator/run`**: Executes custom attack payload against target function in sandbox.

### 3.9 CI/CD Pipeline Generator (`/api/cicd`)
* **POST `/api/cicd/generate`**: Creates GitHub Actions or GitLab CI workflow files.
* **POST `/api/webhooks/github`**: Webhook receiver for GitHub push and pull-request events.

## 4. External API Endpoints (`/api/...`)

### 4.1 AI Specialist & Guardrails (`/api/ai`)
* **POST `/api/ai/ask`**: Contextual security Q&A powered by NVIDIA Nemotron with guardrail enforcement.

### 4.2 Remediation & Streaming (`/api/remediate` & `/api/scan`)
* **POST `/api/remediate`**: Generates root-cause analysis and unified git diff patch for a finding.
* **POST `/api/scan/full`**: Orchestrated static audit + Tavily threat intelligence + Nemotron patch synthesis.
* **POST `/api/scan/stream`**: Server-Sent Events (SSE) progressive streaming endpoint:
  - Event `scan_complete`: Initial AST findings emitted in ~200ms.
  - Event `threat_intel`: Live Tavily CVE advisories emitted in ~1.5s.
  - Event `patch_ready`: Nemotron defensive diff patch emitted upon synthesis.

### 4.3 Threat Intelligence (`/api/intel`)
* **POST `/api/intel/cve`**: Queries Tavily Search for CVE advisories matching a CWE ID or keyword.

### 4.4 Threat Modeling (`/api/threat-model`)
* **POST `/api/threat-model/graph`**: Generates node-and-edge attack trees tracing sources to sinks.

### 4.5 OAuth 2.0 Integration (`/api/auth`)
* **GET `/api/auth/providers`**: Returns configured status for Google and GitHub OAuth.
* **GET `/api/auth/oauth-config`**: Retrieves OAuth configuration details.
* **POST `/api/auth/oauth-config/save`**: Updates and persists OAuth client IDs and secrets to `.env`.
* **GET `/api/auth/github/start`**: Initiates GitHub OAuth flow with CSRF token generation.
* **GET `/api/auth/github/callback`**: Handles GitHub callback and exchanges authorization code for user profile.
* **GET `/api/auth/google/start`**: Initiates Google OAuth flow with CSRF token generation.
* **GET `/api/auth/google/callback`**: Handles Google callback and exchanges authorization code for user profile.
